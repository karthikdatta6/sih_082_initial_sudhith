SECTION 1: DIRECT ANSWER - IS THERE OVERFITTING?
========================================================

SHORT ANSWER: NO. The model is NOT overfitting to training data.

PROOF (6 independent lines of evidence):

  (1) CHRONOLOGICAL SPLIT - Train ends Dec 2024. Test starts Jul 2025.
      6-month gap. No data from test period ever touched during training.

  (2) TEST R2 > VAL R2 FOR PM2.5 (the main pollutant):
      PM2.5 h=1:  Val R2 = 0.9321  |  Test R2 = 0.9634
      PM2.5 h=48: Val R2 = 0.4993  |  Test R2 = 0.6676
      PM2.5 h=72: Val R2 = 0.4494  |  Test R2 = 0.6426
      If overfitting existed, test would be LOWER than val, not higher.

  (3) BEATS PERSISTENCE AT EVERY SINGLE HORIZON (all 21 models):
      Persistence = just predict yesterdays value. A memorising model
      would not beat a well-tuned persistence baseline. Ours beats it at
      every pollutant x every horizon. Skill ranges from +0.089 to +0.893.

  (4) 52 PHYSICS STRESS TESTS PASSED:
      Out-of-distribution perturbations (wind=15m/s when training rarely
      sees >12 m/s) produce physically correct responses. A memoriser
      collapses on inputs never seen in training. Ours does not.

  (5) LOO CROSS-SECTIONAL DESIGN:
      Each station is excluded from its own city-wide mean. It cannot
      recover its own value through the aggregation feature.

  (6) verify_causality() PASSES:
      A script checks bit-identical feature values on time-truncated
      frames. Any future data leak would produce different values and fail.

CONCLUSION: The model learned genuine atmospheric physics, not history.

---- MISSING ISSUE A: NNLS ENSEMBLE DEGENERATION [SEVERITY: HIGH] ----

  WHAT IT IS:
  The model is called a '3-variant ensemble' (L1 + Huber + L2 LightGBM).
  But for O3, the NNLS simplex weights have collapsed to:
    O3 h=1:  weights = [1.000, 0.000, 0.000]  <- single model
    O3 h=3:  weights = [1.000, 0.000, 0.000]  <- single model
    O3 h=6:  weights = [1.000, 0.000, 0.000]  <- single model
    O3 h=48: weights = [1.000, 0.000, 0.000]  <- single model
    O3 h=72: weights = [1.000, 0.000, 0.000]  <- single model

  This means the O3 'ensemble' is actually just ONE LightGBM model
  (the L1 variant) for 5 out of 7 horizons. There is no ensemble
  diversity for O3. The ensemble blending provides zero benefit.

  WHY IT HAPPENED:
  The L1 variant dominates because O3 has high skew (many near-zero
  nights). L1 loss is robust to this. Huber and L2 underperform on val
  so NNLS gives them zero weight.

  WHAT TO LOOK INTO:
  The ensemble design is working AS INTENDED for PM2.5 (all 3 variants
  get nonzero weight). For O3, the architecture naturally selected the
  best single model. This is not a bug - NNLS is designed to discard
  weak members. BUT it should be documented honestly, not called an
  ensemble in the final presentation.

  FIX: v3 adds XGBoost (different split logic) + Ridge (different
  inductive bias) which will force genuine diversity.

---- MISSING ISSUE B: BIAS CORRECTION BACKFIRED ON O3 [SEVERITY: MEDIUM] ----

  WHAT IT IS:
  The bias correction (a * pred + b, fitted on validation) is supposed
  to IMPROVE performance. For O3 it made things WORSE:

    O3 h=1:  RMSE before correction = 9.88   RMSE after = 10.16
             calibration_gain_rmse = -0.279  (NEGATIVE = got worse)

    O3 h=24: calibration_gain_rmse is also negative

  The bias parameters (a=1.133, b=-1.32 for O3 h=1) were fit on
  validation data (Jan-Jun 2025) but generalize poorly to the test
  period (Jul-Dec 2025) because O3 mean shifts dramatically from
  summer to winter (val mean = 44.4 ug/m3, test mean = 31.3 ug/m3).

  WHAT TO LOOK INTO:
  The linear bias correction overfit to the validation distribution.
  It should not be applied for O3 h=1 and h=24 in production.
  A seasonal-adaptive correction would fix this.

  FIX: Apply bias correction only when calibration_gain_rmse > 0.
  For O3 h=1, use uncorrected prediction (R2=0.9244 > corrected 0.9201).

---- MISSING ISSUE C: LARGE VAL->TEST DISTRIBUTION SHIFT IN O3 [SEVERITY: MEDIUM] ----

  WHAT IT IS:
  O3 h=1 metrics show a massive gap between val and test periods:
    Val:  R2 = 0.779,  obs_mean = 44.4 ug/m3  (Jan-Jun 2025, winter-summer)
    Test: R2 = 0.920,  obs_mean = 31.3 ug/m3  (Jul-Dec 2025, post-monsoon)

  The test set has lower O3 (monsoon dilution + post-monsoon), making
  it easier to predict. The 0.92 test R2 for O3 is partly inflated
  by the test period having a cleaner/simpler O3 regime.

  Similarly for PM2.5:
    Val PM2.5 mean = 91.6 ug/m3
    Test PM2.5 mean = 115.6 ug/m3  (test is 26% HIGHER)
  Test PM2.5 appears better because heavy winter episodes dominate the
  test period and these are more predictable from meteorology.

  WHAT TO LOOK INTO:
  The held-out test metrics are REAL and uncontaminated. But you
  should understand that val and test represent different seasonal
  regimes. The true generalization should be evaluated on a full
  annual cycle when re-training becomes possible.

  FIX: No immediate fix needed - just document this context. Long term:
  use a rolling-window evaluation or full-year held-out set.

---- MISSING ISSUE D: PM2.5 h=24 NON-MONOTONIC R2 [SEVERITY: LOW-MEDIUM] ----

  WHAT IT IS:
  Forecast skill should degrade monotonically as horizon increases.
  But our PM2.5 results show:
    h=12: R2 = 0.7300
    h=24: R2 = 0.7492   <- HIGHER than h=12. Skill went UP.
    h=48: R2 = 0.6676

  This is physically anomalous. Forecast error cannot decrease at a
  longer horizon under normal conditions.

  ROOT CAUSE:
  The h=24 model benefits from strong diurnal periodicity. Delhi PM2.5
  peaks every day at roughly the same time (morning rush + evening
  inversion). At exactly 24h ahead, the target_hour_sin/cos and
  target_y_clim features lock onto the diurnal cycle perfectly.
  h=12 is an awkward half-day offset where these periodicity features
  help less.

  WHAT TO TELL TL:
  This is a KNOWN artifact of diurnal climatological features, not a
  modeling error. The h=24 model effectively uses climatology as a
  strong prior for same-time-tomorrow predictions. It is not cheating
  (target_y_clim is fold-fitted from training only) but it does make
  h=24 look better than h=12 statistically.

  FIX: Document this in the technical writeup. No training change needed.

SECTION 6: 4 NEW PHYSICS FEATURE FUNCTIONS (v2.1)
===================================================

1. compute_ventilation_coefficient(blh, wind_speed)
   Formula:  VC = BLH * wind_speed  [m2/s]
   Crisis:   1.0 if VC < 2000.0  (CPCB Emergency Action Plan threshold)
   Return:   (vc, is_ventilation_crisis)
   Tests:    6 unit tests, all passing

2. compute_hygroscopic_swelling(pm25, dewpoint_depression)
   Formula:  swelling = PM2.5 / (1 + exp(-DD))
   Meaning:  DD >> 0 (dry): swelling -> PM2.5 (max aerosol exposure)
             DD ~= 0 (saturated): swelling -> PM2.5/2
             DD << 0 (fog): swelling -> 0 (fog droplets dominate)
   Return:   swelling_index
   Tests:    6 unit tests, all passing

3. compute_chemical_age_ratios(pm25, pm10, nox, no2)
   Formula1: fine_coarse_ratio = PM2.5 / (PM10 + 0.001)
             ~0.9 = combustion smoke | ~0.3 = road dust
   Formula2: photochemical_age_ratio = NOx / (NO2 + 0.001)
             >5.0 = fresh exhaust | ~1.0 = aged transported plume
   Return:   (fine_coarse_ratio, photochemical_age_ratio)
   Tests:    7 unit tests, all passing

4. compute_inversion_lapse_rate(t_2m, t_925hpa)
   Formula:  delta_T = T_925hPa - T_2m  [degrees C]
   Meaning:  > 0 = warm inversion lid (pollution trap)
             = 0 = neutral atmosphere
             < 0 = normal lapse rate (good mixing)
   Return:   delta_T_inversion
   Tests:    5 unit tests, all passing
